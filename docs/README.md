# Artefakte der Fallstudie

Legt ausschließlich die **eigenen**, im Team verabschiedeten Artefakte ab. Ein KI-Vorschlag aus einer Compare-Session ist zunächst **kein** freigegebener Requirement- oder UML-Stand. Führt ihn allenfalls als Vergleich im Lernbericht, nicht ungefragt als verbindliche Spezifikation.

- `product/`: Problem, Ziel, Systemgrenze
- `scenarios/`: Personas, Ziele, Szenarien
- `use-cases/`: strukturierte Anwendungsfälle
- `user-stories/`: eigene User Stories und Akzeptanzkriterien
- `requirements/`: funktionale und Qualitätsanforderungen
- `uml/`: Entwürfe, bevorzugt `.puml` wenn geeignet
- `architecture/`: Komponenten, Schnittstellen, Entscheidungen
- `learning/`: kurze, optionale Lernberichte und Reflexionen
- `lehrende/`: didaktische Grundlagen (nicht in jeden Agent-Prompt laden)

Beschreibt offene Annahmen sichtbar. Änderungen am freigegebenen Stand müssen vom Team entschieden und nachvollziehbar sein. Traceability: Story/Anforderung → Modell/Code → Test, soweit für die Aufgabe relevant.
